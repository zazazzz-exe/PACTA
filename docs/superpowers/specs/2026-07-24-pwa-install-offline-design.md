# Installable PWA + offline completion — design spec

**Date:** 2026-07-24
**Status:** Draft for review
**Scope:** Make the PACTA web app installable ("download the app" / add to home screen)
and complete the existing offline outbox by making the app shell load offline.

## 1. Goal

Two user-visible outcomes, one underlying change:

1. **Installable app.** A user can install PACTA to their phone home screen or desktop,
   launch it in its own window (no browser chrome), and see an in-app **"Download app"**
   affordance that triggers the install.
2. **Offline that actually works.** The installed app **opens while offline**, so the
   already-built outbox flow (compose a Send offline → it queues → auto-sends on reconnect)
   becomes reachable instead of dying on a blank page.

The single underlying change enabling both is adding a **service worker + web app manifest**
via `vite-plugin-pwa`.

## 2. Why this completes the offline feature (not a rebuild)

The offline outbox already works today for real network loss, independent of the demo mode
that was removed:

- `frontend/src/pages/Send.tsx` — when `isOffline()` (`navigator.onLine === false`), a Send
  **queues** via `outboxEnqueue` instead of submitting, and shows a "Queued" screen.
- `frontend/src/components/OutboxBar.tsx` — on the offline→online transition it **auto-flushes**,
  sending each queued payment through `adapter.send` and leaving failures queued to retry.
- `frontend/src/lib/outbox.ts` — `isOffline()`, `useOffline()`, `useOutbox()`, queue storage
  in `localStorage`.

The gap: a plain SPA cannot **load** without the network. A user who opens PACTA while offline
gets a blank page and can never reach the Send screen to queue anything. The service worker
precaches the app shell so the installed app **opens offline**, closing that gap. No new
offline/queue logic is written; this design only makes the existing flow reachable and verifies
it end to end.

## 3. Non-goals / guardrails

- No changes to the frozen Soroban contract, money logic, or `ChainAdapter` behavior.
- No new backend. `/api/risk-lens` and `/api/kyc-*` are untouched.
- No offline **data** caching (portfolio/activity are always fetched live; stale balances are
  worse than a clear offline state). Offline = shell loads + outbox queues.
- No browser extension (deferred; see §9).
- No offline signing — signing a transaction always needs the wallet and the network. Offline
  only queues; the flush on reconnect is what signs and submits.

## 4. Architecture / components

### 4.1 Build: `vite-plugin-pwa`
Add `vite-plugin-pwa` (dev dependency) to `frontend/vite.config.ts`:

- `registerType: 'autoUpdate'` — the SW auto-registers and a new deploy activates silently on
  the next load (Workbox `skipWaiting` + `clientsClaim`). No update-nag UI.
- `workbox.generateSW` — precache the built shell via `globPatterns`
  (`**/*.{js,css,html,woff2,png,svg,ico}`), with `navigateFallback: '/index.html'` so the
  client-side router boots for any route while offline.
- `manifest` — see §4.2.
- `includeAssets` — favicon/logo/apple-touch-icon.
- `devOptions.enabled: false` — keep the SW out of `npm run dev` to avoid caching surprises
  during development; it is exercised via `npm run build && npm run preview`.

### 4.2 Web app manifest
Generated by the plugin:

- `name`: "PACTA", `short_name`: "PACTA"
- `description`: existing tagline copy
- `display`: `standalone`
- `start_url`: `/`
- `scope`: `/`
- `theme_color`: `#F4F2EC` (matches existing `index.html` meta), `background_color`: `#F4F2EC`
- `icons`: 192, 512, and a **maskable** 512 (so Android does not letterbox the logo)

### 4.3 Icons
Source: existing `frontend/public/pacta.svg` (crisp vector) with `Pacta_logo.png` as fallback.
Deliverables written to `frontend/public/`:

- `pwa-192x192.png`, `pwa-512x512.png`
- `pwa-maskable-512x512.png` (logo on a safe-zone-padded solid background)
- `apple-touch-icon.png` (180×180, for iOS home screen)

Generation method: `@vite-pwa/assets-generator` driven by a `pwa-assets.config.ts`, run once as
a build script (`npm run generate-pwa-assets`). Falls back to a one-off `sharp` script if the
generator output needs manual tuning.

### 4.4 `index.html` head additions
The manifest `<link>` is injected by the plugin. Add manually:

- `<link rel="apple-touch-icon" href="/apple-touch-icon.png">`
- `<meta name="apple-mobile-web-app-capable" content="yes">`
- `<meta name="apple-mobile-web-app-title" content="PACTA">`
- `<meta name="apple-mobile-web-app-status-bar-style" content="default">`

(`theme-color` and viewport already present.)

### 4.5 `InstallPrompt` component (`frontend/src/components/InstallPrompt.tsx`)
Owns the "Download app" affordance. Two rendering surfaces share one hook (`useInstallPrompt`):

- **Dismissible top banner** — rendered near `OutboxBar` in `App.tsx`. Appears only when
  installable and not previously dismissed.
- **Profile row** — a permanent "Install app" entry in the Profile page, always available.

Behavior by platform:

- **Chromium / Android:** listen for `beforeinstallprompt`, `preventDefault()`, stash the event.
  Button → `event.prompt()` → await `userChoice`. Hide the affordance after accept.
- **iOS Safari:** `beforeinstallprompt` never fires. Detect iOS (userAgent) and, when not already
  installed, show a short **"Add to Home Screen"** instructions sheet (Share → Add to Home Screen).
- **Already installed:** detect `window.matchMedia('(display-mode: standalone)').matches` (and
  `navigator.standalone` on iOS); render nothing.
- **Dismissal:** banner dismissal persisted in `localStorage` (key e.g. `pacta_install_dismissed`).
  The Profile row ignores dismissal (always shown when not installed).

### 4.6 Offline shell state
No new offline engine. Reuse `useOffline()`:

- The existing `OutboxBar` already renders the offline / queued / delivering / delivered banners.
- Add a plain, friendly **"You're offline"** treatment on data surfaces that would otherwise show
  a spinner or error while offline (Home portfolio, Activity), so an offline-opened app reads as
  intentional rather than broken. Actions that need the network are disabled with a clear message;
  Send remains usable and routes to the queue.

## 5. Data flow (offline drill)

```
Install PWA  →  go offline  →  launch PACTA
   → SW serves cached shell (app opens)         [NEW: enabled by service worker]
   → user uses the already-connected wallet (or reconnects)
   → compose Send → isOffline() true → outboxEnqueue → "Queued" screen   [existing]
   → reconnect → OutboxBar detects offline→online → flush()              [existing]
       → adapter.send() prompts wallet to sign → submit → outboxRemove
   → "Delivered N queued payment(s)" banner                              [existing]
```

## 6. Edge cases / caveats (documented, not blockers)

- **Flush needs a live wallet + signature.** On reconnect, `adapter.send` prompts the wallet.
  If the 15-minute idle auto-lock (`main.tsx`) fired while offline, the user must reconnect
  before the flush can sign. Acceptable; surfaced by the existing connect flow.
- **`navigator.onLine` is coarse** — it reflects the network interface, not real reachability.
  This is existing behavior; unchanged here.
- **SW caching of `sw.js` / manifest** — ensure Vercel does not long-cache the service worker or
  manifest, so updates propagate. Verify `vercel.json` headers; `autoUpdate` + Workbox defaults
  generally handle this, but confirm during verification.
- **StrictMode double-effects** — `beforeinstallprompt` handling must be registered once and
  cleaned up; guard against double registration in dev.

## 8. Verification

- `cd frontend && npm run build && npm run preview`.
- Chrome DevTools → **Lighthouse → PWA**: installable + best-practice checks pass.
- **Install tests:** desktop Chrome (install icon in address bar → own window); Android Chrome
  (Download app button → prompt). iOS Safari (Add to Home Screen instructions → icon appears).
- **Offline drill** (§5) end to end: installed app opens offline, Send queues, reconnect flushes.
- **Already-installed:** confirm the install affordance hides in standalone mode.

## 9. Deferred: browser extension

Not built this cycle. Rationale recorded: PACTA is non-custodial and connects to existing wallets,
so an extension popup would run in a `chrome-extension://` context where injected wallet APIs
(e.g. Freighter) are unavailable — signing would require a clunky workaround (WalletConnect relay
or a signing tab). The PWA already delivers installable, one-click, app-like access on both
desktop and mobile without that problem. Revisit an extension only if PACTA pivots to holding keys,
or for a genuinely extension-native feature (e.g. an in-page Risk Lens on the dApp sites you visit).
